# 홈페이지 버전과 되돌리기 보호 기준

## 복원 범위

공통 정책은 `admin/shared/website-policy.js`에 있습니다. 홈페이지 버전 판정, 과거 상태 복원, 특정 변경 취소, GitHub 간단 롤백, 병합 전 검사가 같은 목록을 사용합니다.

- 허용: `src/content/`, `src/pages/`, `src/styles/`, `src/design-tokens.ts`, `public/media/`, 두 favicon 파일.
- 보호: 위 목록 밖의 모든 파일. 어드민, 워크플로우, 스크립트, 의존성/런타임/빌드 설정, 라우팅, 언어 처리, SEO, 공통 유틸리티, index.html 등이 포함됩니다.
- 이름 변경은 이전 경로와 새 경로를 모두 검사합니다. 심볼릭 링크와 서브모듈은 자동 복원하지 않습니다.

버전 복원은 최신 Git tree를 기준으로 허용된 파일의 차이만 적용합니다. 이후 공통 FE 파일이 변경되었다면 과거 페이지와의 호환성을 보장할 수 없어 복원을 중단합니다. 내용이 이미 같으면 요청을 만들지 않습니다.

특정 변경 취소는 대상 커밋의 모든 변경이 허용 범위 안에 있어야 합니다. 기반 수정이 섞인 커밋을 부분 취소하지 않습니다. 간단 롤백은 main의 first-parent 이력에서 마지막 홈페이지 변경을 찾으며, 어드민만 수정한 커밋은 건너뜁니다. 찾은 홈페이지 변경에 보호 파일이 섞여 있으면 더 오래된 변경을 임의로 선택하지 않고 중단합니다. 결과 PR은 자동 병합하지 않습니다.

## 같은 페이지 파일 안의 기반 수정

파일 안의 특정 수정이 단순 디자인인지, 반드시 유지해야 하는 기반 개선인지는 코드만으로 확정할 수 없습니다.

`src/config/website-compatibility.js`는 보호 기준점입니다. 이번 도입 이전의 버전은 공통 기능이 다른 버전으로 취급합니다. 이후 **되돌려지면 안 되는 버그·보안·기반 로직을 허용 경로 안에서 수정할 때는 이 파일의 값을 같은 커밋에서 증가**시키세요. 가능하면 기반 로직을 보호 경로의 모듈로 분리하세요. 단순 문구·이미지·레이아웃 변경에는 값을 변경하지 않습니다.

새 기준점 이전의 복원/취소는 중단되고, 그 이후의 일반 홈페이지 요청은 계속 되돌릴 수 있습니다. 새 기능·보안 수정과 페이지 변경을 함께 한 PR도 자동 취소하지 않습니다.

## 현재 버전과 직접 수정

GitHub의 경로별 커밋 이력에서 허용된 홈페이지 변경을 조회하고, 연결된 PR은 중복 없이 모읍니다. PR이 없는 수정은 날짜·제목·‘직접 수정’으로 표시하며 PR 번호를 만들어 붙이지 않습니다. 현재 홈페이지 파일의 SHA 목록으로 상태를 비교하므로 어드민/문서만 변경되어도 기존 홈페이지 버전이 유지됩니다.

전체 이력과 페이지 커서는 기존 D1 읽기 캐시에 저장합니다. GitHub 원본은 변경하지 않습니다. 오래전에 작성된 커밋이 오늘 병합되는 경우를 놓치지 않도록 커밋 날짜로 증분 조회를 자르지 않습니다. GitHub 조회 실패를 빈 목록으로 처리하지 않습니다.

## 운영 반영 시 필수 검사 연결

배포 전 `0010_rollback_protection.sql`을 적용해야 합니다. 기존 실행 기록을 보존하면서 `rollback_protected` 결과를 저장할 수 있도록 제약을 확장합니다. 로컬 검토에서는 메모리 DB만 사용하며 운영 DB에는 아직 적용하지 않습니다.

`Rollback Safety / Rollback scope`는 pull_request_target에서 **base의 신뢰한 코드만** 실행합니다. PR 코드 실행, 의존성 설치, 쓰기 토큰은 사용하지 않습니다. 보호 경로 변경 및 새 공통 기능과의 충돌을 검사합니다.

운영 반영 후 GitHub main의 브랜치 보호 또는 ruleset에서 **Rollback scope를 필수 검사로 지정**해야 GitHub UI에서도 실패한 롤백의 병합을 차단할 수 있습니다. 관리자 우회와 직접 main push 권한은 저장소 운영 정책에 따라 별도로 제한해야 합니다. 검토 브랜치에서는 운영 설정을 바꾸지 않습니다.

이 검사는 일반 개발 PR을 차단하지 않습니다. 자동 생성 롤백 브랜치 또는 복원 표시가 있는 PR에 범위 제한을 적용합니다.

## 로컬 검토

`npm run admin:build:review` 후 `MNG_REVIEW_PORT=4203 npm run admin:review`를 실행합니다.

- `/history?example=current`: 어드민 HEAD가 달라도 현재 홈페이지 버전 유지
- `/history?example=direct`: 직접 수정 기록과 상세
- `/history/201?example=protected#restore`: 공통 기능 보호로 복원 제한
- `/requests/101`: 기반 코드가 포함된 요청의 변경 취소 제한

예시 데이터만 사용하며 실제 이슈·PR·홈페이지·운영 DB는 변경하지 않습니다.
